# 交底书编写、反馈修订与申请稿复核

## 从大纲到交底书

用确认稿、技术说明、研发记录、图纸或源码还原方案。先写一句主线，说明什么对象在什么条件下，经过哪些关键处理而得到什么结果。按[项目工作表](../assets/workbook.md)记录关键事实的出处和状态。方案讨论产生的选项由发明人取舍，已确认方案据此更新大纲。文件时间只作线索，基准以明确确认的版本关系为准。

可用下列内容填写接收方模板。栏目名称、顺序、格式、字数与页数按实际模板执行。

| 栏目 | 可交付内容 |
| --- | --- |
| 技术领域与技术问题 | 指明对象、应用条件及遇到的技术困难，用实际可观察的目标界定问题。 |
| 技术背景及相关现有技术 | 背景解释必要概念。逐件说明相关技术怎样实现，附可核对出处。 |
| 现有技术的缺点及原因 | 联系具体手段、适用条件、成因和后果。 |
| 发明目的 | 对应确有依据的困难，写明拟实现的技术目标与适用边界。 |
| 技术方案与具体实施方式 | 从总体组成、流程、部件配合到关键步骤，交代每项功能如何实现。用图和实施例说明。 |
| 关键点和发明点 | 每点给出具体技术手段、对应的对比证据、差异与产生作用的机制。 |
| 有益效果 | 用「区别手段 → 直接作用 → 技术效果」说明。可据结构推导的据实写，定量提升需要相应测量或计算。 |
| 替代方式或其他材料 | 依据模板列出有支撑的替代结构、适用条件、术语、图表或其他帮助理解的材料。 |

## 写出可实施的方案

- **按流程或装置关系展开。** 对每一步写执行主体、输入及来源、处理或连接规则、触发条件、输出及去向。流程要说清正常、边界和异常去向。装置还需说明关键部件的相对关系和工作状态。按理解方案的需要和可用资料安排总图及局部图。
- **区分必要与可选。** 检查去掉、替换某部件或规则后，解决技术问题的机制是否仍成立。把相互配合的特征一起讲清。型号、阈值、算法、实现语言和部署形式的必要性由事实决定。
- **实施例用一种完整配置走通。** 写清输入或初始状态、条件、处理过程及输出。标明实测、代码测试、仿真、手工复算、构造示例或预期效果。演示代码与实际方案边界可追踪，示例参数和验证用值按其用途标注。缺关键事实就列出待确认项及其影响。
- **有公式才核公式。** 对每式记录定义、变量、单位或量纲、输入条件、输出用途及依据。对会改变结论的阈值方向、零分母、边界或异常值做针对性复算。正文、图、实施例和公式的条件保持一致。Word 公式保留 OMML，纯文本提取丢失分式或上下标时回看原式和渲染页。
- **对图按节点核验。** 核对步骤号、箭头、条件分支、图题、正文引用和标签。用可编辑矢量源绘图，导出可嵌入的 SVG、PNG 或接收方指定格式。按实际插入尺寸检查中文、线条、图题位置。需要独立复制的干净图件单独交付。

## 审阅与修订

1. **先读当前指定基准。** 只读任务给定位意见。可结合技术、专利材料和版式三个角度审阅，真实条件、公式、文献覆盖与图文一致是重点。每条意见写「位置、依据、问题、影响、最小改法」，区分影响实现或范围的问题、交付前整理、可选改善。
2. **把反馈映射到具体位置。** 将意见与确认方案、正文和图对应，注明处理方式及理由。有冲突时说明是措辞、实现、前提还是保护范围的改变。在修改方案经明确授权时另存副本，按要求对新增、替换或技术亮点标识。术语处理和措辞修改可用 [Prompt 4–7](prompts.md)。
3. **核实改动范围。** 比较当前稿与基准，检查受影响的步骤、图、公式、技术效果和权利要求；修改授权只有局部时，把范围外的联动需求列作定位意见。突出技术亮点时以具体做法和对比依据定位置。
4. **确认呈现。** 检查原生公式、图、图题、标题、分页、空白页、表格和标色。尽量用最终 Word 客户端导出 PDF，逐页看当前版。纯文字核对和可视核对分别记录实际覆盖。复审逐条关闭已处理意见，指出本轮仍影响交付的事项。

## 接到申请文件初稿时

按本轮要求和已取得材料确定复核范围，以确认交底和有依据的后续修订为基准。复核整套时，对照权利要求、发明内容、具体实施方式、摘要和附图，逐项检查权利要求的对象、各特征及其组合能否在说明书中定位。局部复核时，聚焦指定表述和支撑它的依据。留意引用关系、用词、边界条件、步骤顺序、分支和附图，尤其是总述压缩后弱化的必要条件、缩窄或扩大了的对象范围，以及后文同一结果被写成不同含义的情形。

给出「申请稿位置 → 交底或图文依据 → 实质差异 → 影响 → 建议」。需要修改时用最小变更闭合一致性，同时保留用户要求的标红稿或干净替换件。若用户明确要求起草正式申请文件，按其交付范围、接收方模板及经核实的现行要求推进，先确认核心技术事实和申请主题。

以交底或申请稿复核为目的的交付意见，与正式检索、新颖性或创造性判断、正式提交和授权状态分别表述。
