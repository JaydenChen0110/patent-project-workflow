# 软件演示、操作手册与软著材料

当用户确实需要软件配套时，使用本分支。它跟随已确认的技术方案和可运行版本。交底中的技术特征对应实际页面、运行规则、测试或明确的拟实现事项。

## 从交底到可运行演示

1. **明确覆盖。** 从当前确认稿选能展示核心机制的场景，记录「交底步骤 → 实际模块 → 测试输入 → 可核对输出」。写清规则实现、模拟或占位的范围。按实际用户任务组织页面。
2. **实现和验证。** 使用项目已有技术栈。算法或业务规则先用直接测试核对，再用浏览器走正常、失败和缺项路径。按需核对导入导出和保存、刷新、窄屏、键盘操作，截图用测试数据。运行记录写明覆盖的功能和环境。
3. **界面优化。** 有现有界面时，明确要保留的业务流程。从信息层级、字段可读性、状态反馈、对比度、键盘和响应式布局入手。可用 `impeccable` 做精修，优化后再操作同一主流程确认实现与展示一致。
4. **打包和交付。** 用隔离目录从实际交付包走一次启动和主要操作，记录运行依赖。在线演示须在允许披露的范围及已获准的托管位置发布。

## 写使用手册

以运行版本和真实源码为准。按接收方需要写运行环境、启动、主要任务、保存或导出及问题处理。每节说明操作路径、输入、按钮及预期反馈，截图与对应步骤、构建版本一致。截取最小必要界面，用测试账号或演示文件。参考材料适合借用章节组织。

先确认能运行、截图可核对，再排版 Word。图题、版本号、正文菜单名称和截图一致。手册可独立使用，读者能按步骤复现所写操作。用 [Prompt 8](prompts.md) 起稿。

## 需要增加软件著作权材料时

- 按目标接收方和实际权利人信息决定输出内容与格式。可用 `software-copyright-materials` 提取真实的实现源码，记录选材范围、顺序和排除项，再按选定后端排版。
- 代码材料保留源码和缩进。用实际 Word 渲染测量分页及前后边界，核对代码是否连续、次序是否正确。拆分件或合并件按接收方要求选用。
- 操作手册与代码对应同一版本。信息待确认时，按用户授权先交已完成的代码和手册，标明申请表字段或其他材料的准备情况。
- 获取所选工具当前支持的版本和运行环境。有现成验证报告时用它确定实际后端和输出范围。先行材料、正式登记材料和登记结果各自注明状态。
