# 从发明主题到交底初稿

适用于只提供发明主题、希望先答关键问题，再一次生成整份技术交底书的任务。已给出可成文的方案时，可直接进入生成。

## 1. 读取已有材料和模板

从本轮附件、指定文件和对话中提取使用场景、旧做法与缺点、待解决问题、关键步骤或部件、工作条件、示例和验证记录。遇到多个版本，优先使用用户明确确认的方案。只有会影响核心机制、范围或事实结论的冲突才需要追问。

模板采用本轮上传或指定的版本，未指定时可复用当前项目已确认且仍可读取的模板。同一模板反复使用，可由用户保存在私有目录并提供固定路径。首次未提供时使用 [通用交底模板](../assets/disclosure-template.md)。若用户明确要求采用原模板但文件无法读取，询问模板位置，可并行整理已知方案。多个模板的选择会改变交付且依据不足时，请用户选定。

## 2. 根据主题提问

用户只给主题时，第一轮用编号集中问下面最相关的几项，通常最多四问。将问题里的名词换成从主题可确定的对象或动作，让用户可以用一句话或一个例子回答。已从材料读到的信息直接用。

1. **使用场景与旧方法。** 谁或什么设备在什么情况下遇到问题？原来的做法是什么？它在哪个具体条件下会失败、费时或引入误差？
2. **关键做法与保护重点。** 从触发到结果经历哪些步骤，或有哪些部件怎样配合？哪一个步骤、结构或组合最希望保护？尚未确定的做法可以直接说「待定」。
3. **走通一次。** 给一个实际或拟用的输入、初始状态或操作例子，说明正常输出。若某个异常会改变核心流程，说明何时触发以及如何处理。
4. **证据与实现状态。** 哪些已实现、哪些是确认的拟实施设计？有无对比文献编号、草图、原型、日志、测试或可用的关键参数？文献线索和测试记录可以稍后补。

按方案形态收敛。方法或软件优先追问输入来源、关键判断和输出去向。装置优先追问关键部件、连接或空间关系、状态变化。需要材料或工艺条件才能实施时，追问处理顺序和决定性的条件、范围或依据。题名、参数细值、附图数量、发明人和联系方式一般留到成稿待补栏。模板若确需登记信息，按用户提供的内容填写。

第二轮只追问仍会改变机制、必要条件或保护重点的事实，通常一到两问。先复述有歧义的理解，再让用户选定或纠正。用户暂时只有构想且希望一起设计时，可给有实质区别的候选机制，说明各自取舍。发明人选定后，再按确认的拟实施设计写入正文。

## 3. 何时出稿

知道「具体问题或使用条件 + 至少一种发明人已确认的实现机制 + 可解释的输入或起始条件与结果」即可生成正文初稿。定量数据、图号、精确尺寸、成熟的原型和完整文献一般可后补。启动请求已包含「答完直接生成」时，答案达到这一条件就继续成文。用户也可说「生成初稿」或「先出一版」。

用户要求现在出稿且核心机制仍缺失时，按实际模板生成带待补标记的框架初稿。已知章节写实，在相关实施栏目就地标明缺失的具体技术问题，交付时集中列出，候选设计放在待讨论材料中。明确标注「框架初稿」以便后续补齐。未要求直接出稿且核心缺口仍可由用户回答时，继续关键提问。

## 4. 一次完成生成

1. **提取事实并组织大纲。** 在工作中记录「技术事实、出处、已实现或已确认拟实施、待补」。沿着「场景 → 问题 → 手段 → 直接作用 → 可支持的效果」组织主线。未经确认的设计选择、示例和已验证结果分别写清。
2. **获取和比对现有技术。** 先读用户给的对比件。需要补查时，根据[检索与比对](prior-art.md)仅用可公开的通用对象、工况与手段检索。用户明确离线时仅用所给材料。检索可用时核对候选全文、日期和适当的段号、图号或权利要求。查询缺少可靠正文时，用证据覆盖限定叙述，并继续撰写可成立的部分。每条不足落到「旧手段、限制条件、成因、后果」。来自发明人经验且未经公开资料印证的内容表明出处。
3. **按模板填充。** 读[交底书编写](disclosure.md)。把说明、对比和保护重点映射到模板现有栏目。优先写清执行主体、部件或步骤、关键规则、必要条件、异常路径和一个可追踪的实施例。按需要和已有材料加入工作流程图、系统图或结构图。概念示意图的构造、比例与信息范围按已有材料标注。关键图件缺依据时，在现有相关栏目或私有待核事项中写明待补图及需要体现的关系。
4. **润色并校核。** 按[术语解释与自然化 Prompt](prompts.md)核对名称、条件、量纲、适用范围和术语。确认对比引文能支持相应陈述，实施方式覆盖所列发明点，效果可由机制推出或有证据支撑，图和步骤编号相符。正文保留模板栏目和顺序，清理说明性占位和示例数据。真实缺项用简短的「待确认」保留。Word 使用适用的文档编辑与渲染流程核对当前副本。

## 5. 交付

- **初稿。** 保存在私有项目目录，使用新文件名。给出 DOCX 模板时以副本为基准保留模板样式、表格、页眉页脚和标题层级，交付 DOCX。给出 Markdown、纯文本栏目或使用通用模板时，默认交付 UTF-8 Markdown。用户指定格式时以指定格式为准。当前环境确实无法完成 Word 生成或版面核验时，交付可用的 Markdown 正文并说明缺少的环节。
- **待核事项。** 交付消息简述实质缺项及需补的位置。检索或比对较多时，附私有短表记录文献状态、依据和结论，正文引用尽量保留模板允许的形式。成稿所用材料及接收方模板留在私有项目。
