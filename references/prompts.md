# 可复制的中文专利 Prompt

把方括号中的内容替换为本轮材料或文件位置。只执行指定任务，用户已经提供的材料直接使用。

## 0. 从主题生成整份交底书

```text
用 $patent-project-workflow。发明主题是[主题]，使用[已上传或指定的模板]。
先读我现有的材料，只问会改变技术方案或初稿结论的问题。我会按编号简答。
材料足够后直接生成初稿。用可公开的通用术语检索，标明对比证据、已确认设计和待补事实。
```

已有材料时可直接说「用本对话已提供的方案和模板生成初稿」。仅凭现有材料推进时加上「本轮离线」。

## 1. 检索与筛选相似专利

```text
根据[已确认技术大纲]，提取可公开检索的对象、技术问题、关键处理或结构、用途和中英文同义词。先给出可执行的查询式，然后检索公开文献。已有公开号先逐件核对。
按问题、手段及其配合关系选出最接近的对比资料，说明纳入理由。给出公开号、公开日、来源链接、可取得范围和最相关的段号、权利要求或图号。摘要、可读全文、原版图文和提取缺失分别标明。
用[检索范围或截止日期]限定结论。缺正文或图式时，说明它影响哪条比对，继续完成可核实部分。
```

## 2. 写背景、现有技术、不足与目的

```text
根据[对比文献原文和证据卡]、[确认中的主方案]写[章节范围]。技术背景介绍理解本案所需的概念与通行做法。相关现有技术逐件说明其问题、手段、过程和适用条件，附可定位出处。
每条不足写明对应材料、适用情境、成因和技术后果。在已核原文中未具体说明的内容按证据覆盖描述。发明目的逐项关联有依据的不足，写清希望达到的技术目标。保留可直接放进交底书的版本。
```

## 3. 写具体流程、发明点与技术效果

```text
以[确认稿或图纸]为事实基准，按[接收模板]写[章节]。沿主流程或结构关系逐项说明执行主体、输入来源、具体规则、判断条件、异常去向与结果用途。每项发明点列出对照材料、具体区别、实现位置和发挥作用的机制。
用[实施例或试验记录]贯穿必要环节。分别标出已实现、拟实施、演示示例和待确认事实。核对步骤号、公式符号、单位、图和效果是否一致。交付正文，另列确实会改变方案的待确认项。
```

## 4. 术语替换与白话解释

```text
面向第一次读这份交底书的专利撰写人员，解释[术语或原句]。结合[前后段或图表]说明它指什么、包含哪些要素、在这一步起什么作用，以及删去或宽泛改写会不会改变含义。
给出适合原段的术语和可直接替换的一句话。已有行业术语、图号、符号或字段名需保留时，在首次出现处附短释义，后文保持称谓一致。涉及不同技术对象时分别解释。含义从材料无法确定的地方标为待确认。
```

## 5. 降 AI 味并保留专利逻辑

```text
根据[确认大纲或原始材料]核对[原文]，先指出实质冲突或无依据表述，再做中文润色。可用 humanizer-zh 的编辑方法处理空话、堆叠修饰、制式连接和重复句式。
用可核对的动作、条件和结果组织句子。保留必要术语、执行主体、条件、否定、顺序、单位、公式、引用、结论的确定程度和适用范围。缺证据时保留原有的限定，技术冲突另列建议。输出可直接替换稿，必要时另列术语变更或待确认事实。
```

## 6. 压缩指定段落或精简发明名称

```text
仅处理[段落范围或标题]。段落稿保留[原段落、编号、公式、表格或结构]，在[字数上限]以内，按[统计口径，公式是否计入]计算并报告实际字数。
优先删除重复释义、空泛评价和重复过渡，再合并同义句。保留必要技术特征、关键判断、分支和引用，并保证段间承接。题名稿给出一个首选和必要备选，明确主题类别、核心对象和范围变化，避免把可选应用或实现细节写成题名限制。
```

## 7. 核对交底稿、反馈或申请稿

```text
以[确认交底稿及已采纳反馈]为技术基准，复核[当前稿]。按[本轮范围]检查方案、对比证据、权利要求的说明书支持、附图和当前版呈现。
每条问题给出页码、段号、步骤或图号、证据、影响和最小改法。区分实质冲突、交付整理和可选改善，已落实的反馈标为已关闭。只读时交付定位意见。获准后只改[指定项目]，按[修订色、修订标记或干净替换件]交付副本并核对联动位置。
```

## 8. 用真实软件版本写使用手册

```text
以[可运行版本、源码、测试记录]为准，按[接收方模板]写使用手册。模板提供章节组织方式。实际菜单、按钮、字段、运行环境和返回结果通过操作或源码核对。
先写启动与适用范围，再沿真实任务给出操作、可见结果和恢复方式；只为需要说明的页面用测试数据截图。交付手册、截图对应清单及已验证的运行方式，拟实现功能单列。
```
