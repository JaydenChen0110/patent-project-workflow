# 相似专利检索与现有技术比对

## 先确定要比什么

已有对比件时先核已取得正文和证据位置。用户限定只用所给材料时，在这一范围内完成比较并标明待核项。要求检索或允许补查且确有缺口时，再执行下列检索步骤。

从材料中抽取技术对象、所处环境、要解决的具体问题、核心处理或结构关系、输出或作用。建立一组业务同义词和一组机制同义词。对未公开的组合，拆成可公开的概念分别检索。

- 第一轮从「对象或工况 + 技术问题」「对象 + 关键手段」「关键手段 + 作用」起步。需要扩展时换同义词、英文名称和相邻应用。
- 第二轮从最相关文献沿分类号（IPC/CPC）、引证及同族追查，验证公开时间、文本类型及实际可取得的内容。用户给了公开号时可直接查该号，再按本轮目标补充。
- 按技术问题、关键手段及其配合关系筛选主要对比件。只有对象或标题相似的资料可作背景。每一件候选记录纳入或舍弃的理由，同一文献的不同网页合并引用。
- 交底写作需要的资料优先达到能支撑指定段落的程度。要查特定时间点、法律状态或官方格式时，按相应目标核对官方记录及适用时间。

## 取得可读文本

1. 由网页检索发现候选，在 Google Patents 读公开全文。需要原版图文或核对中国文献书目信息时，从[国家知识产权局专利业务办理系统](https://cponline.cnipa.gov.cn/)进入公布公告或专利检索及分析入口。
2. 记录公开号及文献类型、名称、申请人、公开日、实际来源、取得范围。需要离线阅读时，在私有项目中按文献保存来源 URL、访问日期、HTML 或 PDF、提取的 Markdown。若网页缺图、公式或附件，标记缺失位置，按需从原版 PDF 或其他可核实来源回读。
3. 浏览摘要和独立权利要求定位主线，读说明书和附图补足实现。比较中涉及某个结构、步骤或公式时，回看原文和分支，避免把摘要遗漏、提取缺失或同族文本差异当成文献结论。
4. 技术交底书通常是用来沟通研发方案的材料。比较工作以实际取得的公开说明书、权利要求书和附图为依据。对论文、标准、公开手册，记录原始发表机构或 DOI 和对应位置。

实际取得范围可写为「摘要」「公开全文，图式缺失」「已核原版图文」。尚未取得原版时，用已取得证据完成可成立的部分，把依赖原版的判断留待补核。

## 将证据写成章节

- **技术背景。** 解释读懂后文所需的概念和已有处理方式。注明哪部分来自综合背景，哪部分来自单篇文献。
- **相关现有技术。** 每件按「问题 → 关键手段 → 实施过程 → 适用条件」概括并给出处。读者可据此理解为什么它与本案相关。
- **现有技术的不足。** 用「具体方案 → 适用情境 → 局限成因 → 技术后果」组织。可由规则或结构推出的后果要写出推导前提。只核到部分文本时，写「在已核对的某段或某项权利要求中，未具体说明……」。有明确证据支持的才写成方案本身的限制。
- **区别与目的。** 在对比表中逐件对照同一技术特征，再把得到支持的不足收敛成技术问题，写明本案拟达到的技术目标。描述协同特征时说明它们怎样共同产生作用。

同一判断有多个来源时逐个注明各自支持的事实。基于局部检索得到的区别，用明确可复查的表达交付，供后续检索或专业判断使用。
